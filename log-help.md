Vivify Quest Session Logs

The Vivify Session Log is the most important log

When reporting a problem with Vivify Quest, the Vivify session log is vastly more important than a normal Android Logcat log.

If you can only provide one log, provide VivifySession.txt.

Vivify Quest has its own diagnostics system specifically designed to record what Vivify is doing with maps, bundles, shaders, conversions, rendering features, and per-level failures. The project itself asks for the Vivify session log and per-level report when a map does not work.

The files Vivify Quest generates

Vivify stores its diagnostic files here:

/sdcard/ModData/com.beatgames.beatsaber/Mods/Vivify/

The two most important files are:

VivifySession.txt
VivifyReport.txt

For crashes, Vivify Quest also asks for:

/sdcard/ModData/com.beatgames.beatsaber/logs2/

The repository’s README specifically lists these files as the diagnostics to provide when a map does not work.

⸻

1. VivifySession.txt — REQUIRED

The main file you should provide is:

/sdcard/ModData/com.beatgames.beatsaber/Mods/Vivify/VivifySession.txt

This is the Vivify-specific session log.

It is generated by Vivify Quest while it is processing and playing maps. This is the log maintainers should look at first when investigating a Vivify problem.

It is especially useful for problems involving:

* PC to Quest map conversion
* Shader translation
* Unsupported shaders
* Stand-in shaders
* Bundle loading
* Converted bundles
* Vivify events
* Custom cameras
* Materials
* Blits
* Screen textures
* Rendering settings
* AudioLink
* Map-specific failures
* Crash-guard conversions
* Problems occurring during a particular level

Vivify Quest also has a Debug logging setting. Turning this on provides more detail in the session log.

How to get it

Use a Quest file manager, QuestPatcher, or another method that allows you to access the Quest’s files.

Navigate to:

ModData
└── com.beatgames.beatsaber
    └── Mods
        └── Vivify
            └── VivifySession.txt

Copy VivifySession.txt somewhere you can access it and attach the file to your GitHub issue.

Do not paste the entire log into the issue

Attach the file instead.

If GitHub does not accept the file upload, upload it somewhere accessible and provide a direct link to the file.

⸻

2. VivifyReport.txt — ALSO IMPORTANT

Vivify Quest also generates:

/sdcard/ModData/com.beatgames.beatsaber/Mods/Vivify/VivifyReport.txt

This is the per-level report.

It is particularly useful when a problem only occurs on one or several specific maps.

If you are reporting:

This specific map does not work

you should provide both:

VivifySession.txt
VivifyReport.txt

The session log gives maintainers the broader Vivify runtime information, while the report provides information associated with individual levels.

⸻

3. Android Logcat — SUPPLEMENTARY

Android also maintains a system-wide log called Logcat.

A Logcat can be obtained through ADB:

adb logcat -d > logcat.txt

You can also clear the existing Logcat before reproducing a problem:

adb logcat -c

Then reproduce the problem and dump the log:

adb logcat -d > logcat.txt

If you are using a Quest debugging tool that provides a Logcat or ADB Logcat function, you can use that instead.

⸻

Logcat is NOT the Vivify session log

These two logs are not interchangeable.

VivifySession.txt

Vivify
   |
VivifySession.txt

This is generated by Vivify Quest itself.

It is specifically concerned with what Vivify is doing with the map and its assets.

Android Logcat

Android / Unity / Beat Saber / Mods / System
                         |
                      Logcat

Logcat contains messages from many different parts of the Quest and Beat Saber environment.

It can contain information from:

* Android
* Unity
* Beat Saber
* Other mods
* System services
* Graphics drivers
* Audio
* Networking
* Background processes
* Crashes
* Warnings
* Unrelated applications

Because of this, Logcat can be extremely noisy.

⸻

Why VivifySession.txt is vastly more important

A normal Logcat might tell us:

Unity: Error

or:

AndroidRuntime: FATAL EXCEPTION

That can be useful.

But the Vivify session log can tell us what Vivify was actually doing when the problem occurred.

For example, a Vivify problem could involve:

Map loaded
|
PC bundle detected
|
Bundle conversion started
|
Shader translation started
|
Shader could not be translated
|
Stand-in shader selected
|
Bundle loaded
|
Vivify event executed
|
Rendering failure

That information is much more directly useful to the Vivify Quest developers than thousands of unrelated Android messages.

For Vivify-specific issues, VivifySession.txt should therefore be considered the primary diagnostic source.

⸻

Best way to collect logs

1. Enable Vivify debug logging

Go to the Vivify mod settings and enable:

Debug logging

This causes Vivify to put more detail into its session log.

2. Start Beat Saber

Reproduce the problem.

If possible, reproduce it using the exact level that causes the problem.

3. Close or restart Beat Saber if necessary

Make sure the diagnostic files have been written.

4. Collect these files

At minimum:

VivifySession.txt
VivifyReport.txt

For a crash, also provide the contents of:

/sdcard/ModData/com.beatgames.beatsaber/logs2/

5. Collect Logcat only as additional evidence

If the problem involves a crash, hard freeze, Android-level failure, or other system-level behavior, also provide:

logcat.txt

Do not replace VivifySession.txt with Logcat.

⸻

What to attach to a bug report

Minimum

For a normal Vivify map problem:

VivifySession.txt
VivifyReport.txt

Recommended

VivifySession.txt
VivifyReport.txt
logcat.txt

Crash

For crashes, provide:

VivifySession.txt
VivifyReport.txt
logs2/
logcat.txt

If possible, also provide the affected map or bundle as requested by the main Vivify Quest README.

⸻

Tell us which level caused the problem

Always include the exact level or levels where the problem happens.

For example:

Level:
My Awesome Vivify Map

If the problem happens on multiple levels:

Levels:
- My Awesome Vivify Map
- Another Vivify Map
- Example Map

If it happens everywhere:

Levels:
All levels

This is important because a problem affecting one map can have a completely different cause from a problem affecting every Vivify map.

⸻

If you cannot provide a Vivify session log

If you genuinely cannot access:

VivifySession.txt

say so in the issue.

Do not silently substitute Logcat and assume it is equivalent.

A Logcat can still be useful, especially for crashes, but maintainers should know that the primary Vivify diagnostic information is missing.

⸻

Quick reference

File	Importance	What it is
VivifySession.txt	Highest	Vivify-specific runtime/session diagnostics
VivifyReport.txt	Very high	Per-level Vivify diagnostics
logs2/	High	Beat Saber crash logs; especially important for crashes
logcat.txt	Supplementary	Android/Unity/system-wide diagnostic output
Screenshots/video	Supplementary	Visual evidence of the problem
Map/bundle	Very useful	Useful for map-specific conversion/rendering problems

TL;DR

For a Vivify Quest bug, give us the Vivify logs first.

VivifySession.txt   <- MOST IMPORTANT
VivifyReport.txt    <- Per-level information
logs2/              <- For crashes
logcat.txt          <- Additional/system-level information

logcat.txt is not a replacement for VivifySession.txt.

If you only have time to provide one file, provide:

VivifySession.txt

That is the diagnostic file specifically produced by Vivify Quest and is the most useful starting point for investigating Vivify-specific problems.
