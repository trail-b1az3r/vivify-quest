#### Which logs matter?

**VivifySession.txt is the most important log.** It is generated by Vivify Quest itself and records what Vivify is doing with maps, bundles, shaders, conversions, rendering features, and per-level failures. If you can provide only one file, provide this one.

Vivify stores its diagnostics in:

```
/sdcard/ModData/com.beatgames.beatsaber/Mods/Vivify/
```

Collect these two files for a normal map issue:

- **`VivifySession.txt` — required.** The primary Vivify-specific runtime log for the current launch. It is especially useful for PC-to-Quest conversion, shader translation, bundle loading, Vivify events, cameras, materials, blits, screen textures, rendering settings, AudioLink, and map-specific failures. It is overwritten when Beat Saber starts again.
- **`VivifyReport.txt` — recommended.** The per-level report. Include it whenever a specific map does not work.
- **`vivify_global.txt` — strongly recommended, especially after a crash or restart.** This is the persistent, timestamped Vivify log. Unlike `VivifySession.txt`, it is not cleared on launch: it appends entries from successive sessions, so it can preserve the previous run after a restart. It also records level-teardown breadcrumbs; the last `Vivify level end:` line can identify which teardown step was reached before a crash.

The global log is in the same Vivify folder:

```
/sdcard/ModData/com.beatgames.beatsaber/Mods/Vivify/vivify_global.txt
```

When it grows to about 9 MB, Vivify continues in numbered parts such as `vivify_global-p2.txt`, `vivify_global-p3.txt`, and so on. Collect **all existing `vivify_global*.txt` parts**, not just the first file. Oldest parts are automatically pruned only when the combined global-log storage exceeds about 1 GB. The global log is available in the full build; the Lite build does not write it.

For crashes, also provide the contents of:

```
/sdcard/ModData/com.beatgames.beatsaber/logs2/
```

#### How to collect the files

1. In **Mod Settings → Vivify**, enable **Debug logging**. This adds more detail to the Vivify session log.
2. Start Beat Saber and reproduce the problem. If possible, use the exact level that causes it.
3. Close or restart Beat Saber if necessary so the diagnostic files are written.
4. Use a Quest file manager, QuestPatcher, or another tool that can access the headset's files. Open `ModData/com.beatgames.beatsaber/Mods/Vivify/` and copy `VivifySession.txt` and `VivifyReport.txt`.
5. Copy `vivify_global.txt` and every numbered `vivify_global-pN.txt` part from the Vivify folder. This is particularly important if Beat Saber has already been restarted, because the current `VivifySession.txt` may no longer contain the run that crashed.
6. If the problem is a crash, also collect the files in `ModData/com.beatgames.beatsaber/logs2/`.
7. Attach the files to your GitHub issue. **Attach the files instead of pasting the entire logs into the issue.** If GitHub does not accept an upload, use an accessible file link.

#### Android Logcat is supplementary

Logcat is not the Vivify session log, and the two are not interchangeable. Logcat contains messages from Android, Unity, Beat Saber, other mods, system services, graphics drivers, audio, networking, and unrelated background processes. It can be useful for crashes, hard freezes, and system-level failures, but it is often noisy and does not replace Vivify's own diagnostics.

You can collect Logcat with ADB:

```sh
adb logcat -d > logcat.txt
```

To capture a fresh reproduction:

```sh
adb logcat -c
# Reproduce the problem, then run:
adb logcat -d > logcat.txt
```

#### What to include in your issue

- **Normal map problem:** `VivifySession.txt`, `VivifyReport.txt`, and all available `vivify_global*.txt` files.
- **Recommended extra evidence:** those Vivify files plus `logcat.txt`.
- **Crash:** all available Vivify logs (including every global-log part), the `logs2/` contents, and `logcat.txt`.
- **Map-specific conversion or rendering problem:** include the affected map or bundle if possible.

Always state the exact level or levels where the problem happens. For example:

```
Level:
My Awesome Vivify Map
```

If it happens on multiple maps, list each one. If it happens everywhere, say **All levels**. A problem affecting one map can have a different cause from one affecting every map.

If you genuinely cannot access `VivifySession.txt`, say so in the issue. Do not silently substitute Logcat and assume it is equivalent. Logcat can still help, especially for crashes, but maintainers need to know the primary Vivify diagnostic information is missing.

#### Quick reference

| File | Importance | What it contains |
|---|---|---|
| `VivifySession.txt` | **Highest** | Current-launch Vivify runtime and session diagnostics; overwritten at next launch |
| `VivifyReport.txt` | **Very high** | Per-level Vivify diagnostics |
| `vivify_global*.txt` | **Very high** | Timestamped history across launches; crash/teardown breadcrumbs; include every numbered part |
| `logs2/` | **High for crashes** | Beat Saber crash logs |
| `logcat.txt` | Supplementary | Android, Unity, and system-wide output |
| Screenshots or video | Supplementary | Visual evidence of the problem |
| Map or bundle | Very useful | Evidence for map-specific conversion/rendering problems |

**TL;DR:** Send `VivifySession.txt`, `VivifyReport.txt`, and every available `vivify_global*.txt` file. Include `logs2/` for crashes and Logcat only as additional system-level evidence. The global log preserves earlier sessions; Logcat is not a replacement for Vivify's own logs.

A Quest port of [Vivify](https://github.com/Aeroluna/Vivify) for **Beat Saber
1.40.8**. It plays Vivify maps on the headset, including maps that were only
ever built for PC.


## **discord server:** ***[here](https://discord.gg/Dt7nvFaWym)***



It is built from several community Quest ports merged into one (see
[Credits](#credits)), and adds three things of its own:
- an on-device PC → Quest converter, with its own DirectX → GLSL shader
  translator;
- AudioLink;
- diagnostics for maps that don't work.

What changed in each release is in [CHANGELOG.md](CHANGELOG.md).

## Features

- FULLY WORKING RAYMARCHING SHADERES IN HOLD MY HAND (only in 0.14.7+)

- **Vivify events on Quest:** custom prefabs, materials, blits, cameras,
  screen textures and rendering settings. Blits run at the right point in the
  frame (before or after the skybox, opaque or transparent geometry), as on
  PC, so effects don't draw over the notes.
- **PC maps playable on Quest.**
  - A map with no Quest bundle has its PC bundle converted on the headset.
    If the song folder has no PC bundle, the mod downloads one.
  - Shaders are translated from DirectX to GLES for the Quest's two-eye
    (multiview) rendering.
  - Anything that can't be translated gets a stand-in shader, so it is still
    drawn.
- **Broken Quest shaders replaced.** A shader that a map's Quest bundle
  shipped empty (the mapper's Unity failed to compile it) is replaced by the
  PC build of that shader. The mod downloads the map's PC bundle if needed,
  and merges the translated shader into a cached copy of the Quest bundle.
- **AudioLink:** `_AudioTexture` for any AudioLink shader in a map, and the
  SongCore `AudioLink` capability.
- **Crash guard:** a converted bundle that crashes the game is automatically
  reconverted without shader translation, so the level stays playable.
- **Diagnostics:** a session log and a per-level report on the headset.

## Install

1. Install the `.qmod` from the
   [releases](https://github.com/trail-b1az3r/vivify-quest/releases) with
   QuestPatcher or ModsBeforeFriday.
2. Dependencies (SongCore, CustomJSONData, Tracks, BSML and the rest) are
   installed by your mod manager.

The newest untested build of `main` is the rolling
[nightly](https://github.com/trail-b1az3r/vivify-quest/releases/tag/nightly)
pre-release. It is rebuilt daily when something has changed.

## Settings

All settings are in **Mod Settings → Vivify**.

Two builds are published with each release. **Vivify-v…** has every feature.
**Vivify-Lite-v…** has the feature set of 0.14.7 (with the geometry-shader
setting): the settings added after it are not in that build. Install one of
them, not both.

Everyday settings are at the top of Vivify's menu; **Show Advanced Settings** reveals the rest.
**This Map → Use Windows Bundle** plays the selected map from its converted Windows bundle even when it
ships a Quest bundle, for a Quest build that draws less than its PC build (the choice is kept per map).

| Setting | Default | What it does |
|---|---|---|
| Convert PC Bundles On Device | on | Converts PC-only maps on the headset. |
| Translate Shaders On Conversion | on | Translates PC shaders to GLES. Off: everything uses stand-in shading. |
| Stand-In Shading For Unsupported Shaders | on | Draws shaders that can't run with a simple stand-in instead of nothing. |
| Scene Depth For Map Shaders | on | Renders `_CameraDepthTexture` for maps whose shaders read it (raymarchers, distortion, soft particles). Maps that don't read it skip the extra pass. |
| Effect Resolution % | 100 | Renders map post-process effects at a lower resolution and scales them up. Lower it (75 or 50) if Vivify maps lag. |
| Use Only PC Bundle For Missing Shaders | off | A Quest map whose bundle is missing shaders is played entirely from its converted PC build instead of being patched. |
| Crash Guard | on | After two loads of a converted map that never finish, plays it with grey stand-ins instead. Turn off if maps go grey after crashes caused by other mods. |
| Offscreen Culling (less lag) | on | Animators in a map's prefabs stop updating while nothing they draw is on screen. |
| Far Culling Distance | 0 (off) | Draws nothing farther than this many metres. Try 150-300 on heavy maps; far scenery may disappear. |
| AudioLink | on | Runs AudioLink for maps that use it. |
| Map Realtime Shadows | off | Off: realtime shadows are off for the whole Vivify level, including from lights a map adds (they blacken note bodies on Quest). On: maps may use them. |
| Replay Render Mode | off | While the Replay mod renders a replay (its own or a BeatLeader one), plays converted maps from a single-screen build its renderer can draw. That build is prepared in the background when you select the map. Normal play is unaffected. |
| Blit Fix For Screen Textures (experimental) | off | Builds converted maps' shaders a second time for blits into screen textures, where they otherwise draw nothing. |
| Prepare Shaders Before Playing | off | Compiles a converted map's shaders in the menu after you select it, instead of freezing at song start. |
| Draw Geometry-Shader Effects (experimental) | off | Draws wireframe/exploding-triangle style effects on converted maps without their geometry stage instead of grey. |
| Flat Geometry Effects | off | Upstream fallback that drops geometry stages. Leave off to use the current upstream eye routing; some geometry-generated shapes disappear when enabled. |
| Separate-Eye Renderer (prototype) | off | Uses supported native multiview materials first, including upstream geometry. Retains separate eye renders for unsupported native materials or the optional paired tessellation feature. Experimental; fallback sections can be substantially slower. |
| Triangle Tessellation (heavy, exp.) | off | Adds supported uniform triangle tessellation to the Separate-Eye Renderer's main views. Yoi grass was verified on Quest 3, with substantial frame-time cost. Adaptive tessellation and tessellation in map cameras/blits remain unsupported. |
| Disable Custom Note Visuals | off | Keeps the game's own notes, sabers and debris. |
| Disable All Blits | off | Turns off post-processing effects. |
| Disable Beat 0 Filmgrain Blit | off | Skips film-grain blits that start at beat 0. |
| Disable CreateCamera Depth | off | Stops map-created cameras from rendering depth. |
| Disable Vivify Visuals In Multiplayer | on | Plays Vivify maps without their visuals in multiplayer. |
| Disable VR Center Adjust Handling | off | Lets room recentering move Vivify's cameras and effects. |
| Submit Scores On Vivify Maps | on | |
| Debug logging | off | More detail in the session log. |

**Reset Vivify (clean slate)** (press twice) deletes all converted maps,
crash-guard notes and PC bundles Vivify downloaded into Quest maps, and resets
the settings; use it when maps are stuck grey or broken after an update.
**Redownload All Vivify Maps** (press twice) lists your Vivify maps in
`Mods/Vivify/VivifyMaps.txt`, then replaces each with a fresh BeatSaver
download; use it when maps stay broken even on an older version. A map is
only replaced once its new copy has downloaded.
**Convert All PC Bundles Now** converts every PC map up front. **Force
Reconvert All (ignore cache)** redoes every conversion.

## When a map doesn't work

Send these two files from the headset:

```
/sdcard/ModData/com.beatgames.beatsaber/Mods/Vivify/VivifySession.txt
/sdcard/ModData/com.beatgames.beatsaber/Mods/Vivify/VivifyReport.txt
```

`vivify_global.txt` (and `vivify_global-p2.txt`, ...) in the same folder keeps every session, with timestamps, so an older run can still be sent after a restart.

For a crash, also send `/sdcard/ModData/com.beatgames.beatsaber/logs2/`.
The map's bundle helps too:
- **Quest maps:** `bundleAndroid2021.vivify` from the song folder.
- **Converted maps:** the converted copy from `Mods/Vivify/ConvertedBundles/`.

### Known limits

- **Native geometry eye routing** uses upstream's `gl_Layer` fix and 0.15.12's
  optional right-eye geometry copy.
  Its shaders link offline; both-eye output and performance still need Quest
  validation. Supported native geometry no longer forces separate scene renders.
- **Tessellation** remains partial. The optional Separate-Eye Renderer and
  Triangle Tessellation setting cover a narrow uniform-factor pattern in the
  main view; Lifelike's adaptive pattern and tessellation in authored map
  cameras/blits remain unsupported. Full PC parity and native speed are not
  established. See [the upstream integration record](tools/separate-eye/UPSTREAM_0_15_11.md).
- **A map that needs a feature the Quest's GPU lacks** can look different
  from PC.

## Building

You need [QPM.CLI](https://github.com/QuestPackageManager/QPM.CLI), the
Android NDK, CMake and Ninja (see the
[BSMG Quest modding guide](https://bsmg.wiki/quest/quest-modding-intro.html)).

```sh
python3 scripts/restore-deps.py   # dependencies from GitHub (no qpackages.com needed)
qpm s build
qpm s qmod
```

CI (`.github/workflows/build.yml`) does the same on every push. See
[`scripts/README-deps.md`](scripts/README-deps.md) for dependency sources.

### Tests

The converter, shader translator and parsers are plain C++20 with no Unity
dependency, so they build and test on a desktop under ASan/UBSan:

```sh
g++ -std=c++20 -O1 -g -fsanitize=address,undefined -I include -o /tmp/conv \
    tools/bundleconvert/main.cpp src/VivifyBundleConvert.cpp \
    src/VivifySerializedFile.cpp src/VivifyDxbc.cpp
VIVIFY_CONV=/tmp/conv python3 tools/bundleconvert/run_tests.py
VIVIFY_CONV=/tmp/conv python3 tools/bundleconvert/fuzz.py
```

`tools/shaderscan`, `tools/dxbc`, `tools/texturedecode` and `tools/report`
have their own suites. `.github/workflows/validate.yml` runs them all,
including a glslang compile of every translated program.
